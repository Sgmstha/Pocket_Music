# Android background online audio — v0.4.0-beta.4

Tap a search result, quick pick or **Play** in song options to stream audio through the native media service. It continues after Home, switching apps or turning the screen off. The bottom bar, full player, queue, notification, lock-screen/media controls, widget and sleep timer share that session. Download remains a separate action; streaming does not add a saved song to Library or the chosen download folder. An existing downloaded copy is preferred when available.

**Watch YouTube preview (foreground)** retains the visible official IFrame player and Audio/Video sizing controls. That video preview still pauses when the Activity stops. The app does not keep an invisible video/WebView running: background listening uses the separate native audio path. This is a deliberate change from the earlier foreground-only audio-preview behavior.

NewPipeExtractor resolves public audio in-process, with an eight-second lookup budget. If extraction fails, or its initial audio source cannot play, the existing authenticated yt-dlp resolver is the fallback. It never updates the engine in the playback critical path. Media3 reads online audio directly with a 500 ms startup buffer, 1.5 second rebuffer threshold and 3–15 second forward buffer (4 MiB byte target). Saved files retain Android MediaPlayer. Signed media URLs and safe request headers stay in a bounded eight-entry memory cache for at most five minutes, shortened by the signed URL's expiry. The cache is scoped to account and active network; errors evict the source. No signed URL is persisted or restored after process death. Only expected HTTPS Google video CDN URLs are accepted. Account Cookie/Authorization headers are never forwarded to the audio player. The encrypted YouTube session is leased only for authenticated extraction and temporary files are deleted in finally. Sign-in and rate limits still apply; no automatic rate-limit retry loop is added.

Playback stays in the existing mediaPlayback foreground service rather than the Activity. CPU/network locks are scoped to preparation/playing and released on pause, failure, completion, source switch or Stop. Preparation has a 90-second ceiling for cold-engine/slow-network startup, with cancellation/stale-generation guards. Leaving the app does not cancel it; pausing while loading prevents automatic playback when preparation completes. Starting downloaded audio replaces online playback, and starting a visible video preview stops the native session. No continuous new polling timer, browser, transcoding or audio-file cache is added.

The online queue is kept in memory while the service runs. Tracks reuse valid in-memory sources when available; URLs are not restored after process death. Force-stop, Android/vendor process termination and lost connectivity can still end playback. A normal Home/screen-off transition is supported. The new Wi-Fi-state permission is a normal permission used for the playback Wi-Fi lock; no additional Google login scope is requested.

Implementation follows Android's [MediaPlayer background-service guidance](https://developer.android.com/media/platform/mediaplayer/background), retaining asynchronous preparation, audio focus and the existing MediaSession. The visible YouTube player remains governed by its [API developer policies](https://developers.google.com/youtube/terms/developer-policies).

Install the matching ARM64/ARMv7 APK over beta 3 without uninstalling. Signing identity and package remain unchanged; versionCode 11. Physical-phone/vendor battery and headset behavior still need user validation, so this remains a prerelease.
